## v1.0.0 - 2026-08-30
### Added
* `modules/deploy-managed`, a copy of `modules/terraform-managed` that hands the image, the container environment and the traffic split to a deploy tool rather than to Terraform. It exists as a copy because `lifecycle` `ignore_changes` takes a static list of attribute references, so the behaviour cannot be made opt-in with a variable
* Reverse-proxy sidecar, enabled by `proxy_image`. Ingress moves to the sidecar's port and both probes move with it, since Cloud Run takes ports and probes on one container only. Its CPU is carved out of `cpu` rather than added to it, because Cloud Run sizes the instance from the sum of its containers' limits
* `healthcheck_startup`, so a revision can be kept from taking traffic until its dependencies answer. Without one Cloud Run falls back to a TCP check, where ready means only that the port is bound
* `deletion_protection` and `initial_label`. Requires google >= 6.12.0 and terraform >= 1.3, both of which the module now declares
### Changed
* The module moved into `modules/terraform-managed` and the root declares no resources. Point `source` at that submodule; the module block and the resource keep their names, so the address is unchanged and there is no state to move. Bumping the version without changing the source fails at plan rather than doing anything
### Deprecated
* `healthcheck` is now `healthcheck_liveness`. The old name is still read when the new one is unset, so upgrading needs no edit
### Fixed
* Three changes the service used to re-plan on every run. The service-level `scaling` block and the container name are stated rather than left to the API, which reports both back whether or not they were asked for
* The liveness probe now states the port it checks. It is a computed attribute, so an absent one is filled in by the API and never planned again -- which left probes polling a port the container does not listen on
